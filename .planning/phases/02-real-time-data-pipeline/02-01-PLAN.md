<objective>
Create the Supabase backend infrastructure that polls the ETASpot PHP API every 5 seconds and writes vehicle data to a Supabase database. This is the server-side half of the data pipeline pivot from client-side protobuf to server-side Supabase.

Purpose: Centralize ETASpot data ingestion on the server so all clients receive push-based updates via Supabase Realtime, eliminating per-client API polling.
Output: Edge Function, database migrations (vehicles + position_history tables), and pg_cron scheduling -- all deployable via `supabase db push` and `supabase functions deploy`.
</objective>

<task type="auto">
  <name>Task 2: Create Edge Function that polls ETASpot PHP API with deduplication and position history</name>
  <files>supabase/functions/poll-vehicles/index.ts</files>
  <action>
Create `supabase/functions/poll-vehicles/index.ts` as a Deno-runtime Supabase Edge Function.

The Edge Function must:

1. **Fetch ETASpot PHP API:**
   - URL: `https://auburn.etaspot.net/service.php?service=get_vehicles&includeETAData=1&inService=1&orderedETAArray=1&token=TESTING`
   - Parse JSON response, extract `get_vehicles` array
   - Wrap fetch in try/catch; return 500 with error message on failure

2. **Route ID mapping:**
   - Define constant `ROUTE_ID_MAP: Record<number, string>` with three entries:
     - `215: '215_202_201_156'`
     - `226: '226_32'`
     - `235: '235_93'`
   - All other routeIDs are converted to string as-is: `String(v.routeID)`

3. **Transform and filter:**
   - Filter: `v.inService === 1` (should already be filtered by `inService=1` param, but safety net)
   - Stale filter: `Date.now() - v.receiveTime < 2 * 60 * 1000` (2 minutes)
   - Map PHP fields to DB columns exactly as defined in the vehicles table:
     - `vehicle_id`: `String(v.equipmentID)`
     - `route_id`: mapped via ROUTE_ID_MAP or `String(v.routeID)`
     - `lat`: `v.lat`
     - `lon`: `v.lng` (note: PHP uses `lng`, DB uses `lon`)
     - `heading`: `v.h || 0`
     - `speed`: `0` (not available from PHP)
     - `load`: `v.load || 0`
     - `capacity`: `v.capacity || 0`
     - `next_stop_id`: `String(v.nextStopID || '')`
     - `last_stop_id`: `String(v.lastStopID || '')`
     - `eta_seconds`: `0` (PHP ETAs are garbage per user decision -- NOT used)
     - `on_time`: `v.onSchedule <= 0 ? 1 : 0` (negative or zero onSchedule means on time or early)
     - `is_delayed`: `(v.onSchedule || 0) > 300` (delayed if more than 5 min behind)
     - `timestamp`: `v.receiveTime`
     - `direction`: `v.direction || ''`
     - `raw_minutes_to_next_stops`: `JSON.stringify(v.minutesToNextStops || [])` (stored as raw JSON for reference)
     - `updated_at`: `new Date().toISOString()`

4. **Position deduplication:**
   - Before upserting, fetch current vehicles: `supabase.from('vehicles').select('vehicle_id, lat, lon, heading')`
   - Build a Map of previous positions keyed by vehicle_id
   - Filter to only vehicles whose lat, lon, or heading changed (or are new vehicles not in the previous Map)
   - Only upsert changed rows (saves DB writes and prevents unnecessary Realtime notifications)

5. **Position history append:**
   - For each changed (non-duplicate) vehicle, insert a row into `position_history` with: vehicle_id, route_id, lat, lon, heading, timestamp
   - Use `supabase.from('position_history').insert(historyRows)`

6. **Stale vehicle cleanup:**
   - DELETE from vehicles any vehicle_id NOT present in the current PHP response (vehicles that went out of service)
   - This ensures the vehicles table only contains currently active vehicles

7. **ETA prediction hook point (no-op):**
   - Add a clearly commented section after position history insert: `// --- ETA PREDICTION HOOK ---`
   - Comment: "When XGBoost model is trained, call FastAPI /api/eta/predict here and write predictions to a predictions table. For now, this is a no-op."

8. **Supabase client creation:**
   - `import { createClient } from 'npm:@supabase/supabase-js@2';`
   - Use `Deno.env.get('SUPABASE_URL')!` and `Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!` (auto-injected by Supabase runtime)

9. **Response:**
   - On success: `{ ok: true, count: changedRows.length, total: rows.length }`
   - On error: `{ error: errorMessage }` with status 500

Use `Deno.serve(async (_req) => { ... })` as the entry point.
