**1. Install protobufjs** (NOT gtfs-realtime-bindings — it uses CommonJS require() which causes issues with Hermes/Metro bundler on React Native). Run `npx expo install protobufjs`. Also install the `protobufjs/light` variant is NOT needed — the full `protobufjs` package includes `.decode()` for reflection-based parsing. We need the GTFS-RT proto definition bundled as JSON for protobufjs.

Actually, use a simpler approach: install `protobufjs` and bundle the gtfs-realtime.proto definition. The proto can be loaded from a JSON descriptor. Create the JSON descriptor from the official GTFS-RT proto (https://developers.google.com/transit/gtfs-realtime/gtfs-realtime.proto). Since we cannot fetch at build time, embed the minimal proto definition as a JS object that protobufjs can use with `protobuf.Root.fromJSON()`. Only include FeedMessage, FeedEntity, FeedHeader, VehiclePosition, TripUpdate, TripDescriptor, Position, StopTimeUpdate, StopTimeEvent — the types we actually decode.

Alternative if protobufjs is problematic on Hermes: use `pbf` library (lightweight, zero-dep protobuf decoder) with a hand-rolled decode function matching the GTFS-RT wire format. `pbf` is known to work well in React Native. If using `pbf`, the decode logic needs to manually read fields by tag number from the proto wire format. This is more code but guaranteed Hermes-safe.

**Claude's discretion on protobuf library choice:** Validate that the chosen library works with Hermes. If `protobufjs` fails during implementation (e.g., eval() usage blocked by Hermes), fall back to `pbf`. Document the choice.

**4. Create `src/services/gtfsRealtimeService.ts`:**
Core function `fetchAndDecodeFeeds()` that:
  a. Fetches BOTH feeds in parallel via Promise.all (position_updates.pb, trip_updates.pb)
  b. Decodes each protobuf binary into FeedMessage
  c. Processes trip updates FIRST — iterates entities, for each tripUpdate finds the first stopTimeUpdate with arrival.time > now, stores { nextStopId, etaSeconds, delay } in a Map keyed by tripId
  d. Processes position updates — iterates entities, for each entity.vehicle: skips if no position or no routeId, looks up tripEta by vp.trip.tripId, maps to VehiclePosition interface (using same field mapping as Code/etaspot_reference.ts)
  e. Filters out vehicles with timestamp older than STALE_THRESHOLD_MS
  f. Returns VehiclePosition[] (the filtered, enriched array)

The function must handle errors gracefully — if either feed fails, throw with descriptive message. The caller (polling hook) handles retry.

Follow the exact decode logic from Code/etaspot_reference.ts:
- vehicleId: vp.vehicle.id || entity.id
- routeId: vp.trip.routeId (skip if missing)
- heading: vp.position.bearing || 0
- speed: vp.position.speed || 0
- nextStopId: vp.stopId || tripEta?.nextStopId || ''
- etaSeconds: tripEta?.etaSeconds || 0
- onTime: tripEta ? (tripEta.delay <= 0 ? 1 : 0) : 0
- isDelayed: (tripEta?.delay || 0) > 300
- timestamp: vp.timestamp * 1000 (convert seconds to ms)

**2. Create `src/hooks/useGtfsPolling.ts`:**
A hook that manages the 5-second polling lifecycle:

```typescript
export function useGtfsPolling(): { isConnected: boolean; error: string | null }
```

Implementation:
- Use `useRef` for the interval timer ID and a `isMounted` flag
- Use `useState` for `isConnected` and `error`
- Use `useAppDispatch` to dispatch `setPositions` and `setConnected`

**Poll function (useCallback):**
  a. Call `fetchAndDecodeFeeds()` from the service
  b. On success: dispatch `setPositions(vehicles)`, dispatch `setConnected(true)`, clear error
  c. On failure: dispatch `setConnected(false)`, set error message, do NOT clear positions (keep last known)
  d. Silently catch — no crash, no re-throw

**AppState listener (useEffect):**
  a. On mount: call poll() immediately, then start interval with setInterval(poll, POLL_INTERVAL_MS)
  b. Listen to AppState changes via `AppState.addEventListener('change', handler)`
  c. When app goes to 'background' or 'inactive': clear the interval
  d. When app comes back to 'active': clear any stale vehicles older than 2 minutes by dispatching setPositions with filtered current positions, then call poll() immediately and restart the interval
  e. On unmount: clear interval, remove AppState listener, set isMounted false

**Foreground resume stale clearing:**
On resume to 'active', before the first fresh poll arrives, immediately filter the current Redux positions to remove anything older than STALE_THRESHOLD_MS. This ensures the brief moment between resume and first poll response does not show stale markers. Use `store.getState().vehicles.positions` via dispatch pattern or read from a ref to avoid stale closure issues. Simplest approach: dispatch `setPositions(currentPositions.filter(v => Date.now() - v.timestamp < STALE_THRESHOLD_MS))`.

**Error handling:** Silent failure pattern matching the app's UX conventions. Failed polls just set connected=false. The hook returns `{ isConnected, error }` so consumers can optionally display state but no toasts or alerts on poll failure.
