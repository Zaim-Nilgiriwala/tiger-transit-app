**src/data/stops.ts:**
- Parse ETA-Model/gtfs_data/stops.txt (CSV, 178 rows)
- Export `STOPS: Stop[]` containing all stops with fields: stopId, stopName, lat, lon, stopCode
- Also export `STOPS_BY_ID: Record<string, Stop>` as a lookup map for O(1) access by stopId
- Use the Stop type from src/types/gtfs.types.ts
- Quote handling: the CSV has quoted fields (e.g. "238","Auburn Softball Complex",...)

**src/data/shapes.ts:**
- Parse ETA-Model/gtfs_data/shapes.txt (CSV, 16637 rows)
- Export `SHAPES: Record<string, Coordinate[]>` grouped by shape_id, with points ordered by shape_pt_sequence
- Each Coordinate has { latitude: shape_pt_lat, longitude: shape_pt_lon }
- Use the Coordinate type from src/types/gtfs.types.ts

**src/data/routeStops.ts:**
- This requires joining trips.txt and stop_times.txt:
  1. From trips.txt: build routeId -> Set of tripIds, and tripId -> shapeId mappings
  2. From stop_times.txt: for each tripId, collect stop_id values ordered by stop_sequence
  3. For each routeId, pick any one trip (the first encountered) and use its ordered stop sequence as the canonical stop order for that route
  4. Also build routeId -> shapeId mapping (first trip's shape_id)
- Export `ROUTE_STOP_SEQUENCE: Record<string, string[]>` mapping routeId to ordered array of stopIds
- Export `ROUTE_SHAPE_ID: Record<string, string>` mapping routeId to its shapeId
- These are string-keyed by routeId (matching the ROUTES data format: '242', '11', '5', etc.)

All three files should be generated by reading the CSV files and hardcoding the parsed data as TypeScript constants (same approach as routes.ts). Write a one-time Node.js script to parse the CSVs and generate the .ts files, then run it. Alternatively, manually construct the TypeScript files — whichever is faster. The data is static and changes ~2x per year.
