  <action>
Create a new component that renders the route polyline and stop markers as children of MapView when a route is selected. This component reads all state from Redux (no props needed since it lives inside MapView).

**src/components/map/RouteOverlay.tsx:**

- Read selectedRouteId from `state.ui.selectedRouteId` and selectedStopId from `state.ui.selectedStopId`
- If selectedRouteId is null, return null (renders nothing)
- Read shape coordinates from `state.routes.shapes[selectedRouteId]`
- Read stops from `state.routes.stops[selectedRouteId]`
- Find the route's color from `state.routes.list` by matching routeId, fallback to '#FF8934'

**Polyline (MAP-06):**
- Import `Polyline` from `react-native-maps`
- Render `<Polyline>` with:
  - `coordinates={shapeCoordinates}` (the Coordinate[] from routes.shapes)
  - `strokeColor={routeColor}`
  - `strokeWidth={5}` (4-5px per user decision, use 5 for visibility)
  - `zIndex={1}` (below bus markers, above map)
  - `lineCap="round"` and `lineJoin="round"` for smooth appearance
- For the navy-tinted shadow underneath: render a SECOND Polyline behind the first with:
  - Same coordinates
  - `strokeColor="rgba(12, 35, 64, 0.25)"` (navy-tinted shadow)
  - `strokeWidth={9}` (wider than main to peek out)
  - `zIndex={0}`
  - This creates the visual shadow effect described in the user decision

**Stop Markers (MAP-05):**
- Import `Circle` from `react-native-maps`
- For each stop in the stops array, render a `<Circle>`:
  - `center={{ latitude: stop.lat, longitude: stop.lon }}`
  - Default size: `radius` calculated to produce ~12px visual size. Since Circle radius is in meters, NOT pixels, we need a different approach.

  IMPORTANT: react-native-maps Circle uses radius in meters, not pixels. For fixed-pixel-size stop markers, use `<Marker>` with a custom View instead:
  - Render a `<Marker>` for each stop with `coordinate={{ latitude: stop.lat, longitude: stop.lon }}`
  - `anchor={{ x: 0.5, y: 0.5 }}`
  - `tracksViewChanges={false}` for performance
  - `zIndex={2}` (above polyline, below bus markers which use timestamp as zIndex)
  - Child View: a circular View with these styles:
    - Default (not focused): width/height 12, borderRadius 6, backgroundColor routeColor, borderWidth 1.5, borderColor '#FFFFFF'
    - Focused (stop.stopId === selectedStopId): width/height 20, borderRadius 10, borderWidth 2.5, borderColor '#FFFFFF', plus a navy-tinted shadow for the glow effect (iOS: shadowColor rgba(12,35,64,1) shadowOpacity 0.4 shadowRadius 6, Android: elevation 6)
  - These are View-based markers with tracksViewChanges=false, same pattern as BusMarker

- Wrap the component in React.memo since it only needs to re-render when selectedRouteId, selectedStopId, or the underlying route data changes.

- Export as default.

Do NOT render any text labels on stop markers (those appear in Phase 5 callouts).

- No other changes to BusMarker. The existing React.memo export is fine since opacity will be stable per-render (either 0.3 or 1).

**src/screens/MapScreen.tsx — Integration changes:**

1. **Import RouteOverlay:**
   - `import RouteOverlay from '../components/map/RouteOverlay';`

2. **Read selection state from Redux:**
   - Add: `const selectedRouteId = useAppSelector((state) => state.ui.selectedRouteId);`
   - Add: `const selectedStopId = useAppSelector((state) => state.ui.selectedStopId);`
   - Add: `const routeStops = useAppSelector((state) => selectedRouteId ? state.routes.stops[selectedRouteId] : undefined);`
   - Add: `const routeShapes = useAppSelector((state) => selectedRouteId ? state.routes.shapes[selectedRouteId] : undefined);`

3. **Render RouteOverlay inside MapView:**
   - Add `<RouteOverlay />` as a child of `<MapView>`, BEFORE the BusMarker map (so bus markers render on top)
   - RouteOverlay reads its own state from Redux so no props needed

4. **Bus marker dimming (per user decision):**
   - When selectedRouteId is non-null:
     - Buses matching selectedRouteId get `opacity={1}` (full opacity)
     - All other buses get `opacity={0.3}` (dimmed to ~30%)
   - When selectedRouteId is null: all buses get `opacity={1}` (full opacity, back button restores)
   - Compute opacity inline in the BusMarker map: `opacity={selectedRouteId ? (vehicle.routeId === selectedRouteId ? 1 : 0.3) : 1}`

5. **Map auto-fit on route selection (MAP-07):**
   - Use a `useEffect` that fires when `selectedRouteId` changes (and is non-null)
   - Gather all coordinates to fit:
     - All stop coordinates for the selected route: `routeStops?.map(s => ({ latitude: s.lat, longitude: s.lon }))`
     - All active bus positions for the selected route: `positions.filter(v => v.routeId === selectedRouteId).map(v => ({ latitude: v.lat, longitude: v.lon }))`
     - Combine into a single array
   - If the array has >= 2 coordinates, call `mapRef.current?.fitToCoordinates(allCoords, { edgePadding: { top: 60, right: 40, bottom: Math.round(screenHeight * 0.45) + 20, left: 40 }, animated: true })`
     - Bottom padding accounts for the bottom sheet at half position (user sees the route detail view)
     - Top padding of 60 avoids the status bar area
   - If array has 0-1 coordinates, skip the fit (edge case: route with no data)
   - IMPORTANT: When selectedRouteId changes to null (back button), do NOT refit the camera. Per user decision: "camera stays exactly where it is"

6. **Stop-tap-to-center (ROUTE-09):**
   - Use a separate `useEffect` that fires when `selectedStopId` changes (and is non-null)
   - Find the stop in routeStops by stopId
   - If found, call `mapRef.current?.animateToRegion({ latitude: stop.lat, longitude: stop.lon, latitudeDelta: 0.008, longitudeDelta: 0.008 }, 500)` to center on the stop with a closer zoom and 500ms animation
   - If selectedStopId becomes null (deselect), do nothing (camera stays)
