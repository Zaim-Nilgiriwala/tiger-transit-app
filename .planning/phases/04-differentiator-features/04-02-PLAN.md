  <name>Task 1: Implement timepoint features and speed ratio</name>
  <files>scripts/build_differentiator_features.py</files>
  <action>
Add timepoint feature functions to `build_differentiator_features.py`:

1. **Load timepoint data:**
   - Load `data/processed/timepoints.parquet` (1,958 entries, columns: route_id, stop_id, scheduled_time)
   - Load `data/processed/stop_sequences.parquet` (202 rows, columns: route_id, stop_id, stop_sequence, stop_progress)
   - Convert scheduled_time to seconds since midnight: `pd.to_timedelta(scheduled_time).dt.total_seconds()`

2. **is_timepoint** (vectorized, NOT .apply()):
   - Build a set of (route_id, stop_id) tuples that are timepoints
   - `is_timepoint = pd.MultiIndex.from_frame(df[['route_id', 'target_stop_id']]).isin(tp_index).astype(int)`
   - Or use merge-based approach: merge timepoint existence flag onto observations

3. **scheduled_departure_seconds:**
   - For observations where target_stop_id is a timepoint, look up the scheduled departure time in seconds since midnight
   - Use merge on (route_id, target_stop_id = stop_id) to get the scheduled time
   - NaN for non-timepoint target stops and routes without timepoints

4. **timepoints_remaining:**
   - For each observation, count how many timepoint stops exist between the bus's current position (by stop_sequence from last_stop_id) and the target stop (target_stop_sequence)
   - Pre-build a lookup: for each route, list of timepoint stop_sequences sorted
   - For each row: count timepoint stop_sequences > current_stop_sequence AND <= target_stop_sequence
   - Vectorize using a precomputed mapping per route

5. **time_until_next_timepoint_departure:**
   - For each observation, find the next timepoint stop ahead of the bus on its route
   - Look up that timepoint's scheduled departure time
   - Compute: scheduled_departure_seconds_of_next_tp - current_minutes_since_midnight_ct * 60
   - Use Central Time for time-of-day: `minutes_ct = ((timestamp - pd.Timedelta(hours=6)).dt.hour * 60 + (timestamp - pd.Timedelta(hours=6)).dt.minute)`
   - NaN for routes without timepoints or when no timepoint is ahead

6. **timepoint_adherence:**
   - For each observation, find the most recent timepoint the bus PASSED (by stop_sequence)
   - Look up that timepoint's scheduled departure time
   - Adherence = actual_time_at_recent_timepoint - scheduled_departure_time
   - This requires inferring when the bus was at the timepoint. Approximation: use the observation's current time minus estimated travel time from the last timepoint (based on time since last_stop_id if last_stop_id IS a timepoint, or NaN if it isn't recent enough)
   - Simpler approach: if last_stop_id is a timepoint, adherence = current_minutes_since_midnight_ct * 60 - scheduled_departure_for_that_timepoint. Otherwise NaN.
   - Positive = running late, negative = running early

7. **Routes without timepoints (27, 235):**
   - All timepoint features set to NaN. XGBoost handles NaN natively.

8. **Speed ratio feature** (`compute_speed_ratio`):
   - After historical segments are merged, compute: `speed_ratio = gps_speed_mps / historical_avg_speed_for_segment_hour`
   - Historical avg speed = segment_travel_median-derived speed (approximate: median segment distance / median segment travel time). OR simpler: use the median speed from the rolling features at the same segment-hour-daytype.
   - Simpler approach: compute historical median GPS speed per (route_id, last_stop_id, hour_ct, day_type) from training pings directly. Save as lookup, merge. Ratio = current gps_speed_mps / historical_median_speed.
   - NaN where historical median is NaN or zero.

Timepoint features must be VECTORIZED (no .apply() on 1.2M rows -- would be extremely slow). Use merges, multi-index lookups, and numpy operations.
