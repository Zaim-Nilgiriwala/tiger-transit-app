<task type="auto">
  <name>Task 2: Downsample telemetry and explode into per-stop rows</name>
  <files>scripts/explode_rows.py, data/processed/exploded.parquet</files>
  <action>
Create `scripts/explode_rows.py` following established script patterns.

The script must:

**Step 1 - Load stop sequences:**
Load `data/processed/stop_sequences.parquet` into a dict keyed by route_id for fast lookup.

**Step 2 - Chunked-by-day processing:**
Get unique dates from telemetry. Process one day at a time using PyArrow predicate pushdown:
```python
import pyarrow.parquet as pq
table = pq.read_table('data/processed/telemetry.parquet',
    filters=[('timestamp', '>=', day_start), ('timestamp', '<', day_end)])
df_day = table.to_pandas()
```

**Step 3 - Filter idle vehicles:**
Remove rows where `progress == 0 AND speed == 0` (parked/idle). Also remove rows where `next_stop_id == 0` (no active trip).

**Step 4 - Downsample to ~60s buckets:**
For each (vehicle_id, route_id) group within the day, create 60-second time buckets and keep one row per bucket (the last observation in each bucket, via groupby + last). This reduces ~13.47M to ~750K rows.

**Step 5 - Explode into per-stop rows:**
For each downsampled row:
- Look up the route's stop_sequences (from Step 1).
- Find stops where `stop_progress > row.progress` (stops ahead of vehicle).
- Take the first 8 such stops ordered by stop_progress.
- Create N rows (up to 8), each with the original telemetry columns plus: `target_stop_id`, `target_stop_sequence`, `target_stop_progress`, `stops_away` (1-indexed position in the remaining-stops list).

Use vectorized merge + filter approach (not iterrows):
- Merge each day's downsampled telemetry with stop_sequences on route_id.
- Filter to target_stop_progress > progress.
- Rank by target_stop_progress within each telemetry row, keep top 8.

**Step 6 - Write output:**
Append each day's exploded rows to a list, then concat and write to `data/processed/exploded.parquet`.

**Step 7 - Print summary:**
- Total rows before/after downsample
- Total exploded rows
- Rows per day (min/max/mean)
- Avg stops_away distribution
- Memory peak estimate
- Routes represented, date range

**Important edge cases:**
- If a route_id from telemetry has no entry in stop_sequences (e.g., Route 237 excluded from GTFS), skip those rows and log the count.
- If vehicle progress is beyond all stops (end of route), that row produces 0 exploded rows -- this is correct behavior.
- Exclude Route 237 explicitly (no GTFS data per research).
