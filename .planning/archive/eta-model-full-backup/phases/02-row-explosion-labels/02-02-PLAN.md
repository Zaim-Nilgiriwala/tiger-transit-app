  <action>
Create `scripts/label_join.py` following established script patterns.

The script must:

**Step 1 - Load data:**
- Load `data/processed/exploded.parquet` (the exploded per-stop rows from Plan 01).
- Load `data/processed/arrivals.parquet` (actual arrival times with route_id, stop_id, vehicle_id, arrival_timestamp).

**Step 2 - Prepare for merge_asof:**
- Both DataFrames must be sorted by the merge key (timestamp).
- The exploded rows have a `timestamp` column (UTC datetime). The arrivals have `arrival_timestamp` (UTC datetime).
- Rename arrivals' `arrival_timestamp` to `actual_arrival` for clarity after join.
- The `by=` parameter must include `['route_id', 'target_stop_id', 'vehicle_id']` to match within the same vehicle/route/stop combination.
- In exploded rows, the target stop column is `target_stop_id`. In arrivals, it is `stop_id`. Rename arrivals' `stop_id` to `target_stop_id` before the join.

**Step 3 - Execute merge_asof:**
```python
pd.merge_asof(
    exploded.sort_values('timestamp'),
    arrivals_prep.sort_values('actual_arrival'),
    left_on='timestamp',
    right_on='actual_arrival',
    by=['route_id', 'target_stop_id', 'vehicle_id'],
    direction='forward',
    tolerance=pd.Timedelta('2h')
)
```
Direction='forward' finds the NEXT arrival after the telemetry observation (the bus hasn't arrived yet, we want when it WILL arrive).

**Step 4 - Compute label:**
```python
df['time_to_arrival_seconds'] = (df['actual_arrival'] - df['timestamp']).dt.total_seconds()
```

**Step 5 - Filter labels:**
- Drop rows where actual_arrival is NaT (no match found within 2h tolerance).
- Drop rows where `time_to_arrival_seconds <= 10` (too close, noise).
- Drop rows where `time_to_arrival_seconds > 7200` (should not happen with 2h tolerance, but safety check).
- Drop rows where `time_to_arrival_seconds <= 0` (negative = arrival was before observation, should not happen with direction='forward').
- Per-route outlier removal: drop labels above the 99.5th percentile within each route_id.

**Step 6 - Timezone bug check:**
Check for a spike at 3600s (+/- 60s) in the label distribution. If more than 5% of labels fall in 3540-3660 range, print a WARNING about possible timezone mismatch. Both telemetry and arrivals should be UTC already (Phase 1 converted both).

**Step 7 - Write output:**
Write to `data/processed/labeled.parquet`.

**Step 8 - Print comprehensive summary:**
- Total exploded rows (input)
- Rows with successful label match
- Label join success rate (matched / total, target >60%)
- Label distribution: min, 25th, median, 75th, max, mean, std
- Rows in 3540-3660s range (timezone check)
- Rows removed by each filter (too_close, too_far, negative, outlier)
- Per-route match rates
- Final output row count and file size

**Important:** The arrivals data has `vehicle_id` as string format. The telemetry data also has `vehicle_id`. Ensure types match before merge_asof (both should be string). Also ensure route_id types match (both int).
