  <name>Task 1: Create evaluate.py with all four EVAL requirements</name>
  <files>scripts/evaluate.py</files>
  <action>
Create `scripts/evaluate.py` -- a single evaluation script that loads the tuned model and test data once, then produces all four deliverables. Follow the established project pattern (sys.path insert, import from build_differentiator_features, MODELS_DIR, argparse).

**Install dependency first:**
```
pip install shap==0.49.1
```
Verify installation succeeds. SHAP 0.49.1 is the last version supporting Python 3.10.2.

**Script structure:**

1. **Imports and setup:**
   - `matplotlib.use("Agg")` BEFORE importing shap (headless rendering -- critical)
   - Import from `build_differentiator_features`: `FEATURE_COLS_V2`, `CATEGORICAL_COLS_V2`, `TARGET_COL`, `load_featured_v2`
   - Define `EVAL_DIR = MODELS_DIR / "evaluation"` and create it
   - Reuse helper functions: `mae()`, `rmse()`, `mape()`, `stops_bucket()`, `tod_bucket()` from existing patterns (copy them into this script -- do NOT import from train_advanced.py since those scripts are not designed as importable modules)

2. **Data loading (shared across all sections):**
   - Load `df_test = load_featured_v2("test")`
   - Extract: `X_test`, `y_test`, `test_route_ids`, `test_stops_away`, `test_scheduled` (scheduled_time_to_target), `test_distances` (distance_to_target), `test_minutes` (minutes_since_midnight), `test_hour_ct`
   - Load tuned model: `bst = xgb.Booster(); bst.load_model("models/tuned_v1.ubj")`
   - Create DMatrix: `dtest = xgb.DMatrix(X_test, label=y_test, enable_categorical=True)`
   - Load best_iteration from `tuned_metrics.json` (do NOT rely on `bst.best_iteration` -- may not persist through UBJSON save/load). Use `iteration_range=(0, best_iter + 1)` for prediction.
   - `y_pred = bst.predict(dtest, iteration_range=(0, best_iter + 1))`

3. **EVAL-01: Comprehensive sliced metrics**
   - Compute `overall`: MAE, RMSE, MAPE, n
   - Compute `per_route`: for each unique route_id, compute MAE, RMSE, MAPE, n. Include sample count.
   - Compute `per_stops_bucket`: buckets "1", "2-3", "4-6", "7+" using `stops_bucket()`
   - Compute `per_time_of_day`: "morning" (6-11), "midday" (11-14), "afternoon" (14-18), "evening" (else) using `tod_bucket()`
   - Compute `per_distance_bucket`: IMPORTANT -- the existing distance_bucket() thresholds put ALL 296K samples in "<1km". Instead, examine `df_test["distance_to_target"].describe()` and compute quantile-based thresholds (use 25th, 50th, 75th percentiles of the actual data distribution). Create 4 buckets with descriptive labels based on actual ranges. If all values are truly tiny, use the raw percentile ranges as bucket labels (e.g., "<0.05", "0.05-0.12", "0.12-0.25", ">0.25").
   - Save to `models/evaluation/eval_metrics_sliced.json`
   - Print summary table to stdout

4. **EVAL-02: SHAP explainability analysis**
   - Use the two-path SHAP strategy from 06-RESEARCH.md:
     - **Path A (try first):** `explainer = shap.TreeExplainer(bst, feature_perturbation="tree_path_dependent")`. Subsample to 1000 rows for TreeExplainer (full 296K too slow). `shap_values_obj = explainer(X_sample)`
     - **Path B (fallback):** If TreeExplainer raises ANY exception, use `bst.predict(dtest, pred_contribs=True, iteration_range=(0, best_iter + 1))`. Slice off bias column: `shap_vals = contribs[:, :-1]`, `base_val = float(contribs[0, -1])`. Construct `shap.Explanation(values=shap_vals, base_values=np.full(len(shap_vals), base_val), data=X_test.values, feature_names=list(FEATURE_COLS_V2))`
   - **Global importance:** `shap.plots.bar(shap_values_obj, show=False)` -> save to `eval_shap_global.png` at dpi=150, bbox_inches="tight". Then `plt.close()`.
   - **Sample selection for waterfall plots:**
     - Compute absolute errors: `abs_errors = np.abs(y_test - y_pred)`
     - Sample 1 (high error): index at 95th percentile of errors
     - Sample 2 (low error): index at 5th percentile of errors
     - Sample 3 (typical): index closest to median error
     - If using pred_contribs fallback (full 296K SHAP values), index directly into shap_values_obj. If using TreeExplainer subsample, find the closest matches within the 1000-sample subsample.
   - **Waterfall plots:** For each of the 3 samples, call `shap.plots.waterfall(shap_values_obj[idx], max_display=15, show=False)`, then `plt.tight_layout()`, `plt.savefig(...)`, `plt.close()`. Save as `eval_shap_waterfall_{1,2,3}.png`.
   - Print which path was used (TreeExplainer or pred_contribs fallback) and the top 10 features by mean absolute SHAP value.

5. **EVAL-03: Comparison table vs naive baseline**
   - Load prior phase metrics from JSON files: `baseline_metrics.json`, `differentiator_metrics.json`, `tuned_metrics.json`. Extract overall MAE and RMSE from each.
   - Compute naive baseline MAE per route from test data: for each route, `naive_mae = mae(y_test[mask], test_scheduled[mask])`.
   - Compute tuned model MAE per route (already done in EVAL-01).
   - Build comparison data structure:
     - `overall`: list of {model, mae, rmse, vs_naive_pct} for Naive, Baseline(P3), Differentiator(P4), Tuned(P5)
     - `per_route`: for each route, {route_id, naive_mae, tuned_mae, improvement_pct, verdict: "WIN"/"LOSS"/"TIE"}. Win = tuned < naive, Loss = tuned > naive. Include sample count.
   - Save to `models/evaluation/eval_comparison.json`
   - Generate `models/evaluation/eval_comparison.md` -- a formatted markdown file with:
     - Overall comparison table (all phases)
     - Per-route comparison table with WIN/LOSS column
     - Summary: X/Y routes won, Z routes lost

6. **EVAL-04: Residual bias detection**
   - Compute signed residuals: `residuals = y_pred - y_test` (positive = overprediction = bus arrives sooner than predicted)
   - Overall residual stats: mean, median, std, pct_overprediction, percentiles (p5, p25, p50, p75, p95)
   - Per-route bias: for each route, compute mean_residual, median_residual, pct_overprediction, n. Flag bias as "OVER" (mean_res > 15s), "UNDER" (mean_res < -15s), or "OK". Threshold of 15s is ~12% of overall MAE.
   - Per-time-of-day bias: same structure as per-route, using tod_bucket()
   - Per-stops-bucket bias: same structure
   - Save to `models/evaluation/eval_residuals.json`
   - Generate two plots using matplotlib:
     - `eval_residuals_by_route.png`: horizontal bar chart of mean signed residual per route. Color bars red (>15s), blue (<-15s), gray (OK). Add vertical line at 0. Label bars with route_id.
     - `eval_residuals_by_tod.png`: bar chart of mean signed residual per time-of-day period. Same coloring scheme.
   - Both plots: title, axis labels, dpi=150, bbox_inches="tight", plt.close() after save.

**Add argparse:** `--section` flag accepting "metrics", "shap", "comparison", "residuals", "all" (default "all"). This allows rerunning individual sections.

**Important implementation notes:**
- Use `matplotlib.use("Agg")` as the very first matplotlib-related line, before any other matplotlib or shap imports
- Always `plt.close()` after every `plt.savefig()` to prevent memory leaks
- For SHAP waterfall, use `show=False` parameter
- When loading prior metrics JSONs, the XGBoost metrics are typically nested under an "xgboost" key -- check the actual structure and handle both flat and nested formats
- For naive baseline metrics, the scheduled_time_to_target column IS the naive prediction (use it directly as y_pred_naive)
- Print progress to stdout for each section
